# Stage 1: Arrive

The user is asking: is this what I came for, and what do I do here?

Starts at the entry point (an ad, a search result, a shared link, an app launch, a prompt fired inside the product) and ends when the user reads for detail or picks something. Hand-off rules and severity: [journey.md](../journey.md).

## Hand-off in

Write down what the user decided before this screen: search terms, a plan clicked on a pricing page, a cart, a destination, the task they were doing when a prompt fired. The first view shows it (AR2) and asks for nothing already decided. When the entry point is outside the product (an ad, an email), read its promise and check that the first view keeps it; when you cannot see the entry point, record it as not observed.

## Rules

### Applies when: always

**AR1. A clear job, a clear first read.** Name the action the screen exists to get and the element read first. If you cannot name the first read, users cannot either. Fix: one primary action; size, weight and position follow the order of the user's questions. Screens that serve several jobs (a home page, a dashboard, a two-sided marketplace) name their top two or three jobs in priority order, give the first one the strongest action, and walk each job's path. U7jTCgIWS4w 1:45. Craft.

**AR2. Show the commitment already made.** Destination, cart, chosen plan. Fix: keep it visible so the remaining decision is small, and keep it visible in later stages. zr37ibqXl1U 9:13. Presenter.

**AR3. Show the real thing.** Decorative art, stock photos and logos say nothing about what the user gets. Fix: the product itself (its output, the dish, the room), sized for its job. zr37ibqXl1U 4:20; U7jTCgIWS4w 0:44. Presenter.

### Applies when: the first view has images, a list or a catalog

These three are screen-craft rules and count toward the Polish cap.

**AR4. Images sized for their job.** A 56 px thumbnail identifies; it does not make anyone want the thing. Fix: size images to persuade where the image is the reason to act; make the first item worth scrolling past. The fold moves with device height, fixed bars and text size, so design the first view by priority, not a pixel count. U7jTCgIWS4w 0:55-1:36. Presenter.

**AR5. No competing decoration.** A photo row above a photo list splits attention. Fix: icons or text for navigation rows. U7jTCgIWS4w 2:53. Craft.

**AR6. Works with any content.** Overlays readable only on the current photo; text set on uploaded images; catalog photos that clash. Fix: a container behind overlay icons; names and numbers off the photo; one photo style per catalog. GGg61sdEjeI 0:36, 2:00; U7jTCgIWS4w 4:09. Craft.

## Honesty items here

HO2 (urgency banners and countdowns on landing), HO6 (ratings, review and user counts in the hero). Details in [honesty.md](../honesty.md).

## Build moves

- **Write the job and the arrival.** One sentence each: the action this screen exists to get; who arrives, from where, and what they already decided on the way (a search, a cart, a chosen plan). The second sentence decides what can be left off the screen (AR2).
- **Start from real content.** Use the product's real images, names, prices and counts before styling. Placeholders hide weak content and wrong lengths. Pick images that show what the user gets (AR3, AR4).
- **Design the first view by priority.** First, second, third read, decided before layout (AR1).
